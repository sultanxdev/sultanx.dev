## Overview

Waani is an India-first developer platform for building AI-powered phone agents.

I’m building Waani to simplify the infrastructure behind voice AI applications. Instead of integrating telephony, realtime audio streaming, speech-to-text, LLMs, and text-to-speech separately, developers can build their voice agent around a single platform.

The project focuses on the engineering problems that appear when voice AI moves beyond a demo — realtime communication, conversation state, provider failures, latency, authentication, and multi-tenant architecture.

---

## The Problem

Building an AI phone agent looks simple from the outside, but the underlying system involves several moving parts.

A developer typically needs to connect:

- Telephony
- WebSocket audio streaming
- Speech-to-text
- LLMs
- Text-to-speech
- Conversation state
- Call lifecycle management
- Authentication and APIs

The difficult part is making all of these components work together reliably while keeping the conversation responsive.

I wanted to build the infrastructure layer that handles this complexity so developers can focus on the actual voice experience and business logic.

---

## The Solution

Waani provides a unified developer-facing layer for building and operating AI voice agents.

A developer can:

1. Create an AI agent
2. Configure its instructions and language
3. Connect a phone number
4. Receive or initiate a call
5. Run a realtime AI conversation
6. Store and inspect the conversation
7. Manage everything through APIs and a dashboard

The goal is to make voice AI integration feel more like working with a developer platform than stitching together multiple infrastructure services.

## What I Built

### Voice Agent API

Created APIs for managing agents, configurations, organizations, API keys, and calls.

### Realtime Voice Runtime

Built the realtime communication layer using WebSockets to handle bidirectional audio during active calls.

### AI Pipeline

Connected speech-to-text, LLM processing, and text-to-speech into a single conversational flow.

### Conversation State

Implemented multi-turn conversation handling so the agent can maintain context throughout a call.

### Telephony Integration

Integrated Exotel for Indian phone connectivity and call handling.

### Call Management

Added call lifecycle tracking, call history, transcripts, and call details.

### Multi-Tenant Architecture

Designed the application around tenant isolation so each organization's agents, calls, and data remain separated.

### Provider Abstraction

Separated external providers behind interfaces so STT, LLM, TTS, and telephony providers can be changed independently.

## Technical Challenges

### Realtime Latency

Voice applications are much less forgiving of latency than normal web applications.

A slow API response can be annoying. A slow voice response makes a conversation feel broken.

Because of that, the system treats realtime communication and provider latency as first-class concerns.

---

### Provider Failures

The voice pipeline depends on multiple external services.

A failure in STT, LLM, TTS, or telephony can interrupt the entire conversation.

I added explicit timeout and failure handling so an external provider cannot keep a voice session waiting indefinitely.

---

### Conversation State

A voice agent needs to understand the current turn while also remembering previous turns.

Waani keeps conversation state separate from the transport layer so the voice session can continue across multiple interactions.

---

### Provider Dependency

Using a single provider creates a strong dependency on that vendor.

Waani therefore uses provider-neutral interfaces instead of coupling business logic directly to individual providers.

This makes future provider changes and fallback strategies much easier to introduce.

---

### Multi-Tenancy

The platform is designed for multiple organizations using the same infrastructure.

Tenant ownership is enforced at the backend and database layer rather than relying on frontend filtering.

## Developer Experience

The intended workflow is:

**Sign up → Create Agent → Configure Agent → Connect Phone Number → Make a Call → Inspect Transcript**

The API is the primary interface, while the dashboard provides configuration and operational visibility.

Example:

```ts
const agent = await waani.agents.create({
  name: "Support Agent",
  language: "hi-IN",
  instructions: "You are a helpful support agent."
});

const call = await waani.calls.create({
  agentId: agent.id,
  to: "+91XXXXXXXXXX"
});
Current Status

Waani is currently in active development.

The first milestone is deliberately focused on one complete workflow:

Create an agent → connect an Indian phone number → make a real call → have a multi-turn AI conversation → save the transcript → inspect the call in the dashboard.

More advanced capabilities such as provider fallback, multilingual support, voice evaluation, model routing, and advanced observability will come after the core voice loop is reliable.
