## Overview

Zyvan is a production-oriented webhook delivery system designed to guarantee reliable event delivery to third-party endpoints.

Unlike naive webhook implementations that rely on best-effort HTTP calls, Zyvan introduces **durable acknowledgment, queue-driven dispatching, idempotent ingestion, and failure-aware retry orchestration**.

**Primary focus:** reliability, failure isolation, and secure outbound delivery.

---

## 🚨 Problem

Typical webhook systems suffer from:

- lost events during transient failures  
- duplicate deliveries  
- tight coupling between ingestion and delivery  
- lack of retry visibility  
- SSRF attack surface  
- poor delivery observability  

At scale, these issues become operationally expensive.

## 🏗️ Architecture Overview

### High-Level Flow

```mermaid
flowchart LR
    A[Client Event] --> B[API Ingest]
    B --> C[(PostgreSQL)]
    C --> D[BullMQ Queue]
    D --> E[Worker]
    E --> F[Outgoing Proxy]
    F --> G[Customer Endpoint]
    G --> H{Response}
    H -->|2xx| I[Delivered]
    H -->|Fail| J[Retry Scheduled]
````

### Core Components

* **API Layer (Node.js + Express)** — validation and ingestion
* **PostgreSQL** — durable source of truth
* **BullMQ + Redis** — retry orchestration
* **Worker Service** — webhook dispatcher
* **Outgoing Proxy** — SSRF protection
* **Next.js Dashboard** — delivery visibility
* **Docker + AWS** — deployment

**Design principle:** queue-first, failure-aware delivery.

## ⚙️ Key Technical Decisions

### Durable Acknowledgment Boundary

**Decision:** Reliability boundary occurs at DB commit.

**Impact:**

* clients stop retrying safely
* Zyvan owns delivery lifecycle
* eliminates ghost failures

---

### Idempotent Ingestion

**Decision:** Enforced unique idempotency keys.

**Impact:**

* duplicate-safe processing
* predictable delivery semantics
* safer client retries

---

### Queue-Driven Retries

**Decision:** BullMQ with exponential backoff.

**Impact:**

* non-blocking retries
* failure isolation
* controlled retry storms

---

### SSRF-Safe Delivery

**Decision:** All outbound calls routed through proxy.

**Protections:**

* IP filtering
* DNS validation
* private range blocking

**Why it matters:** webhook systems are common SSRF vectors.
